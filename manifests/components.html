# HobbyX Design System

Code version of the HobbyX (Hobby Index) design system: a dark-only marketplace and portfolio app for
trading-card and collectibles collectors. These docs are light for easy reading; every component is shown on the
dark app background, as in the product. Everything here is built from the Figma DS: the same variables,
the same component properties, the same names.

## How it is built

| Layer | Source in Figma | In code |
|---|---|---|
| **Tokens** | Variables: primitives, semantic colours, spacing, radius, typography | `tokens/source/*.tokens.json` (W3C DTCG) → Style Dictionary → `--hx-*` CSS variables |
| **Typography** | 125 text styles `text <size>/<leading>/<weight>` | 3 composable classes: `hx-text-sm hx-font-medium` |
| **Components** | Component sets with Variant / Boolean / Text properties | React + TypeScript; each prop is named after its Figma property |
| **States** | Variants `State = Hover / Pressed / Focus / Disabled` | Native CSS states (`:hover`, `:focus-visible`, `:disabled`), not props |

Every value in component CSS is a token. To change a colour, change the variable in `tokens/`
and run `npm run tokens`; every component updates.

## What is inside

- **Foundations:** Colors, Typography, Spacing & Radius.
- **Actions:** Button, IconButton.
- **Forms:** Input, Checkbox, Radio, Switch.
- **Display:** Badge, Avatar, Tabs, Skeleton.
- **Feedback:** Alert, Toast, EmptyState, StatusIcon.
- **Overlays:** Menu / DropdownMenu.
- **Patterns:** MarketplaceCard: a real product card composed only from DS components.

## Principles

1. **Figma is the source of truth.** Code mirrors names and structure, so designers and developers talk
   about the same `variant="ghost" size="sm"`.
2. **Semantic tokens only.** Components use roles (`stroke/mute`, `bg/main`), never raw hex.
3. **Accessible by default.** Native `<button>` and `<input>`, visible focus rings, `role="switch"`,
   `aria-*` on menus and tabs, `prefers-reduced-motion` respected. The a11y panel checks every story.

## Found during the audit (next steps for the Figma DS)

- Badge: red and yellow `bg` ↔ `text-icon` variable names are swapped; the dot is always grey.
- Typography: italic styles use the Regular face; "medium 10" styles are Regular; no semantic text roles yet.
- Avatar placeholder uses `bg/primary dark`, identical to the app background, so the circle disappears.
- Toast uses a raw Tailwind colour (`emerald/900`) instead of a semantic variable.
- Icon-only Button: `Icon` sm keeps a 20 px icon while Blur / Transparent sm use 16 px.
- No Dialog / Bottom sheet component in the DS, although the product uses bottom sheets.

### Contrast fixes (v1.1)

An automated a11y check (axe, WCAG AA needs 4.5:1 for text) found five failing pairs. All of them are fixed in v1.1:

| Token | Where | Before | Fix | After |
|---|---|---|---|---|
| `typography/Mute` on `bg/primary dark` | Input, Checkbox, Radio, Switch descriptions | zinc/500 · 4.09:1 | → zinc/400 | 7.7:1 |
| `typography/Mute` on `bg/secondary dark` | Inactive Tabs | zinc/500 · 3.7:1 | → zinc/400 | 7.0:1 |
| `typography/Mute` on `bg/blur` | Menu shortcuts | zinc/500 · 3.74:1 | → zinc/400 | 7.1:1 |
| Destructive link text | Destructive link button, Menu hint | `typography/Destructive dark` red/700 · 3.05:1 | → `typography/Destructive` red/500 | 5.3:1 |
| Badge pink filled (pink/50 text) | Badge | on pink/600 · 4.2:1 | → pink/700 | 5.5:1 |

`Destructive dark` stays in the DS: it is meant for light surfaces, it was used on a dark one by mistake.
Muted icons and borders keep zinc/500: non-text elements need 3:1, and they pass.
The only remaining flag is the Disabled Input (2.06:1). WCAG exempts disabled controls from contrast rules.
After the fixes all 86 stories pass the check.

# Typography

One family: **Momo Trust Sans** (Google Fonts, SIL Open Font License). Weights 400 / 500 / 600 / 700.

In Figma every text style is named `text <size>/<leading>/<weight>` — 125 styles in total.
In code they are not 125 classes: a style = **size + leading + weight**, combined from three small classes.

```html
<p class="hx-text-sm hx-font-medium">…</p>          <!-- text small/leading-normal/medium -->
<h2 class="hx-text-2xl-tight hx-font-semibold">…</h2> <!-- text 2x large/leading-none/semibold -->
```

- **leading-normal** — fixed line height in px. Body text, multi-line.
- **leading-none** (`-tight` in code) — line height as a ratio: 120% (10–12 px), 130% (14–20 px), 100% (24 px +). Headings, numbers, single lines.
